Chrome asks for a separate justification per permission. Paste each block into
the matching box on the Privacy tab.

================================================================
storage
================================================================
Stores the user's own settings locally: their Gemini API key, their category
rules, their written goals and content rules, and a cache of verdicts already returned by the
model. The cache is what keeps the extension cheap - a video that has been
judged once is never sent again. Nothing in storage is transmitted anywhere;
there is no developer-operated server.

================================================================
Host permission: *://*.youtube.com/*
================================================================
The extension has to run on YouTube because that is the only place it does
anything. On a watch page the content script reads the details of the video
being opened (title, channel, description, tags, YouTube category, length -
through a small read-only main-world script that asks the player for this video
ID's data), pauses the player while the video is judged, and then
either releases playback or covers the player with a blocking screen. Optional
feed filtering, off by default, uses the same access to hide tiles before they
are clicked. No other site is matched.

================================================================
Host permission: https://generativelanguage.googleapis.com/*
================================================================
This is the Google Gemini API endpoint that judges a video. It is the only host
the extension ever sends a request to. The request carries the video's details
(title, channel, description, tags, YouTube category, length) and - in the Smart
(default) and Thorough modes - the video's public YouTube link, which Google's
own servers fetch to process the video. It is authenticated with the user's own Google AI
Studio key in the x-goog-api-key header. There is no other network destination:
no analytics, no telemetry, no error reporting, no developer backend.

================================================================
Remote code
================================================================
Answer: NO, I am not using remote code.

The package contains the complete, readable source. There is no build step, no
minification and no bundler. There is no eval(), no new Function(), and no
externally hosted script or stylesheet. The only network call returns JSON data
that is parsed and acted on - never executed.
